# シミュレータから実機へ（Go2 + Z1）

Genesis 上で学習がうまくいった方策を、Unitree Go2（脚）＋ Unitree Z1（腕）の実機へ載せるまでの手順です。

現状のリポジトリは **学習・推論はシミュレータ**、表示用に **ROS 2（rviz）ブリッジ**までです。実機 SDK への直接送信コードはまだありません。下の手順は、その実装を足すときの設計指針と作業順です。

座標の約束: Go2 `base` は **+X が前（グリッパ側）**、**+Z が上**。行動は **22 次元**（CPG 15 + 腕残差 6 + グリッパ残差 1）。観測は **81 次元**。

---

## 0. 前提チェック（シミュレータ側）

実機に出す前に、次を満たしていること。

| 項目 | 目安 |
| --- | --- |
| 段階 | 載せたい課題（例: `walk` / `reach` / `carry`）で再生が安定 |
| 重み | `logs/{algo}_…/ppo_XXXXXX.pt`（または `bc_trot.pt` / `gail_trot.pt`） |
| 次元 | チェックポイントの `obs_dim=81`、`act_dim=17`、`arm=z1` |
| 制御 | 脚は CPG→12 関節 PD、腕は IK ベース＋残差（reach 以降） |
| 方向 | 教師・方策の前進が +X（`scripts/diag_trot_direction.py` で確認可） |
| 動画 | `videos/<タスク>/…` の再生で転倒・逆走が少ない |

```powershell
# 例: 歩行 easy の最新を 1 体再生
.\.venv\Scripts\python.exe -m pick_and_carry.train_ppo --play --resume latest --num-envs 1 --easy-walk --curriculum walk --arm z1 --log-dir logs/ppo_curriculum_walk_easy --seconds 20 --record play_check.mp4
```

## 1. 何を実機に載せるか（インターフェース）

学習済みネットは **観測 → 行動 22** だけです。実機ではその前後を自前でつなぎます。

```text
[実機センサ] → 観測 81 を組み立て
       ↓
[ActorCritic]  mean_action(obs)  →  a ∈ R^17
       ↓
[展開]  CPG 15 → 脚 12 目標角（脚位相・軟結合・接地引き込み）
        腕 6 / 指 1 →（必要なら IK ベース + 残差）→ 腕・指目標角
       ↓
[低レベル]  PD / Unitree SDK の位置指令（約 50 Hz = dt 0.02 s）
```

再利用したいモジュール（シミュレータ非依存）:

| モジュール | 用途 |
| --- | --- |
| `pick_and_carry/agents.py` | 方策の読み込み・推論 |
| `pick_and_carry/cpg.py` | `LegCPG` で CPG→脚 12 |
| `pick_and_carry/ik.py` / `control.py` | 腕 IK ベース＋残差、グリッパ |
| `pick_and_carry/observation.py` | 観測の並び（実機値を同じ順に入れる） |
| `pick_and_carry/checkpoints.py` | `ppo_*.pt` のロード |

シミュレータ専用（実機ループでは呼ばない）: `env.py` の Genesis シーン、報酬、カリキュラム進行。

## 2. 推奨ステップ（段階的に実機へ）

一度に箱運びまで出さず、段階を踏む。

### ステップ A — 机上・安全確認

1. 緊急停止・電源・ケーブル長を確認する。
2. 脚は吊り下げ／台上、腕は可動域内で干渉しない位置。
3. 低レベルが **位置制御（PD）** で動くこと、指令周波数を約 **50 Hz** に合わせられることを確認する。
4. シミュの kp/kd（脚 60/1.5、腕 80/8、指 20/2）をそのまま使わず、**実機メーカ推奨値から始め**、必要なら近づける。

### ステップ B — ゼロ方策・開ループ

1. 方策を出さず、立ち姿勢の固定指令だけで脚・腕が安定するか。
2. `TrotTeacher` 相当の開ループ CPG（または `diag_trot_direction` と同じ前進）を短時間だけ流し、**前進がグリッパ方向**か目視する。
3. ここで前後が逆なら、実機の関節符号／マウント向きを直し、シミュの `_SAGITTAL_SIGN` と食い違わないようにする。

### ステップ C — 方策オン（歩行だけ）

1. `easy-walk` または平地歩行の重みをロードする。
2. 観測は最低限: 関節角・角速度、IMU（重力・角速度）、指令速度、直前の脚指令（CPG 展開後 12）。無いセンサはシミュと同じ正規化で 0 埋めせず、**推定またはホールド**する。
3. 行動マスクが歩行用なら腕指令は送らない（シミュの `locomotion_action_mask` と同じ）。
4. 短時間・低速指令から始め、転倒したら即停止。

### ステップ D — 腕（到達・箱）

1. 手先・箱・目標の位置を、胴体座標で観測スロットに入れる（カメラ／モーションキャプチャ／既知物マークなど）。
2. シミュ同様、EE 目標 → 数値 IK → 残差を足して Z1 へ送る。
3. 把持は力・電流・視覚のいずれかで「掴めた」を決め、シミュの把持フラグに相当する信号を観測へ入れる。

### ステップ E — 屋外・不整地・フルタスク

1. ドメインランダマイズ（摩擦・押し・腕乱れ）ありで再学習した重みを優先する。
2. 段差・傾斜はシミュの振幅より弱いところから。
3. 箱運び・キャッチは、センサ遅延と物体追跡がボトルネックになりやすい。遅延が大きいなら観測に遅れを入れて再学習する。

## 4. シミュレーションと実機のギャップ（対策）

| ギャップ | 対策の例 |
| --- | --- |
| 摩擦・接地 | 学習時 `randomize_friction` / 押しあり。実機はゆっくり指令 |
| 遅延 | 観測遅延をシミュに入れて再学習。指令を一段平滑化 |
| 質量・慣性の誤差 | URDF は公式寄りだが、実機キャリブ後に微調整 |
| センサノイズ | キャッチの `noisy` 段階や、観測ノイズを足した再学習 |
| PD ゲイン差 | 実機推奨ゲインで追従を合わせ、必要ならシミュ側ゲインを寄せて再学習 |
| 前後・関節符号 | 必ず前進テスト。符号が違うと BC/GAIL/PPO すべて逆向きになる |
| 自己衝突オフ | シミュは自己衝突オフ。実機は干渉チェックと可動域制限を必須に |

ドメインランダマイズを強めた重みで移す方が、sim 専用の綺麗な重みより実機向きです。

## 5. いまのリポジトリでできること / まだないこと

**できること**

- シミュで学習・`--play` 再生・mp4 確認
- `--ros` で状態を JSON 共有し、WSL の rviz2 で可視化・クリック目標（実機制御ではない）
- 方策・CPG・IK・観測レイアウトを実機プロセスから import

**まだないこと（実機適用時に追加する）**

- Go2 / Z1 公式 SDK への指令送信
- 実機センサ → 観測 81 のアダプタ
- 安全停止・トルク制限・運用 UI
- 実機データでの微調整（少数ショットの BC / 短いオンロボット RL など）

表示だけ試す（シミュ＋rviz）手順は README の「推論中に運び先を動かす」を参照。

## 6. 作業の進め方（まとめ）

1. シミュで対象段階の重みを確定し、再生動画で品質を見る。  
2. 実機では開ループ → 歩行方策 → 腕付きの順に載せる。  
3. 観測・行動・周波数・座標をシミュと同一契約にする。  
4. ギャップが出たら、まず符号・遅延・ゲインを疑い、必要ならドメインランダマイズ强化で再学習。  
5. 実機 SDK アダプタを `scripts/deploy_real.py` 等としてリポジトリに足す。
