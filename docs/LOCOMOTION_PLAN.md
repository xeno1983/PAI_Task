# 歩行の改善案と課題の統廃合

作成日: 2026-10-17。最終課題は「飛んできたボールをキャッチ」。
この文書は調査と提案です。コードはまだ変更していません。

## 1. 状況

- 歩行を 25740 回まで学習した。報酬は 0.115 前後、`tracking` は 0.72、`gait` は 0.64、`steady` は 0.94 で止まっている。
- 動画では動きが不自然に見える。
- 報酬の値は、動きの自然さを測れていない。

## 2. 確認できた原因

### 2.1 方策のばらつきが増え続け、指令が両端に振り切れている

歩行の重みの `log_std` から標準偏差を見た結果です。

| | 0 回 | 12880 回 | 25740 回 |
|---|---|---|---|
| 脚の標準偏差の平均 | 0.39 | 1.73 | 1.73 |
| 腕の標準偏差の平均 | 1.15 | 2.53 | 2.51 |
| 脚の指令が 0.95 を超える割合 | 0% | 28% | 29% |
| 脚の指令の大きさの平均 | 0.27 | 0.70 | 0.70 |

- 歩行では腕を固定しているので、腕の指令は報酬に効かない。それでも標準偏差が増えた。増加の原因はエントロピー項の押し上げである。
- エントロピーは tanh を通す前の正規分布で数えている。tanh で上限に張り付いても罰が出ない。報酬が頭打ちになると、増加だけが続く。
- 毎ステップほぼ全開で動かす指令になり、ぎこちない動きに見える。

### 2.2 一般的な四脚の設定と違う

比較元は次の3つです。

- [Genesis の Go2 歩行例](https://genesis-world.readthedocs.io/en/latest/user_guide/policy_training/examples/locomotion.html)
- [legged_gym](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/envs/base/legged_robot.py)
- [Walk These Ways](https://ar5iv.labs.arxiv.org/html/2212.03238)

| 項目 | 一般的な設定 | このプロジェクト |
|---|---|---|
| 関節の剛さ（kp / kd） | 20 / 0.5 | 80 / 4 |
| 指令の振れ幅（action_scale） | 0.25 rad | 0.50 rad |
| 観測 | 直前の指令を含む | 含まない |
| 学習率 | KL に合わせて自動調整 | 固定 |
| ばらつき | 小さい初期値から下げる | 増え続ける |
| 外乱・摩擦の乱数化 | あり | なし |
| 失敗判定 | 胴体や太ももの接地 | 傾き 60 度、高さ 0.18 m |

### 2.3 足の運びの報酬が弱い

- 標準は、足が一定時間浮いてから着地したときに点を出す `feet_air_time` と、足を上げる高さである。
- いまの `gait` は、ある瞬間に対角の2本が着いているかだけを見ている。足を持ち上げずに引きずる動きでも点が取れる。
- Walk These Ways は、罰が課題の点を飲み込まないよう、課題の点 × exp(罰の和) にしている。

### 2.4 キャッチの準備になっていない

- キャッチの観測はボールの位置だけである。`ball_in_base` が返す速度は捨てている。動くボールの先読みができない。
- ボールは地面を転がるだけで、飛んでこない。
- 歩行中は腕を固定している。脚は腕が動いたときの重心移動に対応する練習をしていない。腕は約 5 kg ある。
- 立つは、足の届く高さの上限が 0.32 m で、目標の 0.40 m に届かない。歩行から先は、しゃがみではなく立った姿勢が基準で、立つ、座るの回数は引き継がれない。

## 3. 提案

### 3.1 課題の統廃合

- **歩行**（立つ・座る・歩行・不整地を1本化）
  - 指令に速度ゼロを含め、静止もここで覚える。
  - 段差の高さは自動で上げる。
  - 腕はランダムな姿勢に動かし、脚に重心移動の補償を覚えさせる。
  - 立つ、座る、ジャンプはメニューから外す。
- **到達**（新設。箱運びの代わり）
  - 胴体の前の指定点に手先を合わせ、握る。
  - 脚は立ったまま支える。
- **キャッチ**
  - 手の前で静止、転がるボール、飛んでくるボール、観測ノイズの順に上げる。
  - 飛んでくるボールは放物線で、投げ位置と速度をばらす。
  - ボール速度と、予測した到達点を観測に入れる。使っていない `goal_pos` と `command` の枠を使うので、観測は 81 のまま増えない。
  - 参考: [Event-based catching](https://arxiv.org/html/2303.17479v2)（到達点の予測）、[Catch It!](https://doi.org/10.1109/icra55743.2025.11127596)（2段階学習）、[Playful DoggyBot](https://arxiv.org/html/2409.19920v3)（手先から見た相対位置の報酬）。
- **箱運び**（持ち歩き、ピック＆プレース）
  - 到達とキャッチがあれば必須ではない。
  - 元の課題として残すなら、到達の後ろの枝にする。

### 3.2 進め方

1. **歩行だけの比較**（各 2000 回ほど。64 台で約 1 時間ずつ）
   - A: ばらつきの上限を決めるだけの修正。
   - B: A に、標準の報酬、kp 20、action_scale 0.25 を加える。
2. 良かった方を歩行の基準にして、到達とキャッチを足す。
3. 飛んでくるボールは、静止、転がる、飛ぶの順で、前の段階の成功率が出てから進める。

### 3.3 比較に使う指標

報酬の値では比べない。次で比べる。

- 指令が 0.95 を超える割合。現在は約 28%。
- 指令の変化量（直前との差の大きさ）。
- 足の浮いている時間と、足を上げる高さ。
- 胴体の傾き（ロール、ピッチ）のばらつき。
- 動画。

## 6. 実施状況（設定を標準に合わせた）

コードは変更済み。実機での学習結果は未確認。

### 6.1 方策と PPO（`agents.py`、`train_ppo.py`）

| 項目 | 以前 | 今 |
| --- | --- | --- |
| 方策の出力 | tanh で −1〜1 に押さえる | 正規分布のまま。環境が 0.25 rad 倍にする |
| 初期のばらつき | 0.37（log_std −1） | 脚 1.0、腕と指 0.4。上限は 1.0 |
| ネットワーク | 256×256 | 512×256×128 |
| 学習率 | 3e-4 固定 | 1e-3 から。KL 0.01 を目安に 1.5 倍ずつ上下（1e-5〜1e-2） |
| エポック、分割 | 4、512 個ずつ | 5、バッチの 1/4 ずつ（`--minibatch-size` で上書き可） |
| 価値損失 | 係数 0.5 | 係数 1.0、クリップ付き |
| エントロピー | 0.005（tanh の手前で計算） | 0.01（出力そのもので計算。上限があるので増え続けない） |

学習ログに `kl`、`lr`、`entropy`、`jerk` を足した。

### 6.2 観測

- 脚の角度は、立ち姿勢との差にした。
- 直前の脚の指令 12 個を末尾に足した（`obs[69:81]`）。範囲は ±5 で切る。

### 6.3 制御

- action_scale 0.5 → 0.25。
- kp / kd は 80 / 4 → **60 / 1.5**。Go2 の例の 20 / 0.5 は、Z1 を載せた重さ（約 5 kg 増）を支えきれない。立ち姿勢を保たせて測ると、kp 20 は沈んで跳ねを繰り返し、30 は 0.23 m、40 は 0.29 m、60 は 0.305 m、80 は 0.313 m で止まった。60 は Go2 と同じ kd/kp の比で、箱を持つ段階にも余裕がある。

### 6.4 歩行と不整地の報酬（`curriculum.py` の `locomotion_reward`）

legged_gym の標準の項目に置き換えた。重みは `config.py` の `LocomotionScales`。

| 項目 | 重み |
| --- | --- |
| 並進速度の一致 | +1.0 |
| 旋回速度の一致 | +0.5 |
| 上下の速度 | −2.0 |
| 横揺れ、縦揺れの角速度 | −0.05 |
| 胴体の高さ（目標 0.30 m） | −50 |
| トルク | −1e-5 |
| 関節の加速度 | −2.5e-7 |
| 指令の変化 | −0.01 |
| 足を 0.5 秒以上浮かせる | +1.0 |
| 太ももとすねの接触 | −1.0 |
| 転倒（胴体の接地を含む） | −5 |

- 合計が負なら 0 に切る。転倒の分はその後に引く。
- 罰は脚の指令だけで数える。腕の指令は罰に入らない。
- ログ用に `tracking`（以前と同じ 0〜1 の一致度）、`gait_score`、`steady`、`jerk` を残した。`rough` の難易度の判定は `tracking` のままなので、以前の曲線と比べられる。

### 6.5 乱れ（歩行と不整地の学習時のみ。再生時は無し）

- 15 秒ごとに、ロボットごとにずらして、水平の速度を ±0.5 m/s 加える。
- 床との摩擦をロボットごとに 0.5〜1.25 倍にする。

### 6.6 そのほか

- 歩行と不整地は、胴体が地面に触れても転倒とする。
- 形の違う古い重みがある保存先で新しく学習を始めると、重みと記録を `old_<日時>` に移してから始める。`logs/ppo_curriculum_walk` の観測 69 の重みもこれで残る。
- 立つ、座る、ジャンプの報酬は変えていない。kp と action_scale が変わったので、立つ、座るは前より届きにくくなっている可能性がある。統廃合のときに見直す。

### 6.7 次にやること

1. 歩行だけを 2000 回ほど学習し、3.3 の指標で見る（`jerk`、`gait`、`steady`、動画）。
2. 良ければ、3.1 の統廃合（到達、飛んでくるボール、歩行中の腕の乱れ）に進む。
